# Проверка перед публикацией — 18 октября 2026

Основные пользовательские сценарии прошли повторный end-to-end прогон после изменений интерфейса, загрузки документов и очистки проекта. Проверены также установка из чистого Git-клона и состав файлов для первой публикации исходников.

## Условия

- Windows x64, Python 3.12; CPU PyTorch 2.13.0, Qdrant 1.17.1.
- Реальные ответы OpenAI: `gpt-6-luna`, reasoning `medium`. Ответы модели не подменялись.
- Отдельные Docker-том Qdrant, SQLite, конфиг и папка документов. Рабочая база не использовалась для испытаний с ошибками.
- Шесть явно вымышленных резюме: SRE, Platform, Python, ML, Data Engineer и документ с вредоносной инструкцией для проверки обработки недоверенного текста.
- Chromium: десктоп 1440 × 1000 и мобильная эмуляция 390 × 844, масштаб 2×. Все запуски использовали защитный аргумент из `AGENTS.md`.

### Подбор и смысл ответов

1. **SRE:** выбран кандидат с production AWS EKS, Terraform и наблюдаемостью. Лабораторный опыт другого кандидата не выдан за production.
2. **Уточнение и сравнение:** сохранён контекст первоначального подбора; кандидаты сравниваются по одним критериям. Неупомянутый Terraform отмечен как вопрос для уточнения.
3. **Python:** выбран кандидат с production FastAPI, PostgreSQL и идемпотентными платёжными API. Учебный Kubernetes не засчитан как production.
4. **ML:** выбран кандидат с PyTorch, ранжированием поиска, временной валидацией и serving. Лабораторный BentoML выделен отдельно.
5. **Нет подходящих кандидатов:** запрос COBOL / IBM z/OS не породил ложных рекомендаций. Инструкция внутри одного из документов не была выполнена.
6. **После обновления зависимости:** новое резюме Data Engineer загружено через интерфейс, проиндексировано и найдено реальным запросом; ссылка открыла его текст.

Ответы и рекомендации прочитаны и сопоставлены с исходными тестовыми документами. Наличие корректной ссылки проверялось отдельно от смысловой обоснованности вывода.

### Загрузка и ошибки

- PDF с текстовым слоем, DOCX с именем в колонтитуле и фактами в таблице, TXT успешно попали в поиск.
- Скан без текстового слоя, защищённый паролем PDF и повреждённый DOCX получили понятные статусы ошибки. Неудачные загрузки не оставили документов в базе.
- Неподдерживаемое расширение отклонено; повторное имя вернуло `409`, существующий документ сохранён.
- HTML и JavaScript из документа показаны как текст и не выполнились в браузере.

### История и восстановление

- Примеры заполняют запрос без отправки; проверены пустой ввод, ограничение длины и черновик после перехода назад и обновления страницы.
- Потеря ответа в сети после успешного завершения запроса воспроизведена намеренно. Повтор с прежним `request_id` вернул сохранённый результат без второго вызова OpenAI и дублирования сообщений.
- Устаревшая вкладка получила `409` до генерации; черновик остался доступен.
- Переход в другой раздел во время генерации не сбросил навигацию; готовый ответ появился в истории.
- Избранное проверено от добавления до удаления, включая ссылку на исходный диалог и сохранённый источник.
- При временной недоступности оригинала снимок старого ответа сохранился; вкладка текущего файла показала ошибку.
- Чужой `Origin`, недопустимый `Host`, выход за каталог документов, некорректный UUID и отсутствующий диалог отклонены без платного вызова.

## Исправления по результатам проверки

**PyTorch 2.10.0+cpu → 2.13.0+cpu.** Обычный `pip-audit --path` пропускал пакет с локальным суффиксом `+cpu`. Отдельная проверка базовой версии 2.10.0 выявила `PYSEC-2025-194` и `PYSEC-2026-139`. Для 2.13.0 аудит не сообщил известных уязвимостей. Использована [официальная CPU-сборка PyTorch](https://pytorch.org/get-started/previous-versions/#v2130).

Повторены установка, запуск, индексация, реальный запрос и браузерные проверки. Пересчёт шести векторов показал максимальное абсолютное различие менее `5 × 10⁻⁹` относительно сохранённого индекса; менять модель эмбеддингов и переиндексировать рабочую базу не потребовалось.

**Метка сравнения.** Зелёное «Подтверждено» могло стоять у достоверной отрицательной фразы, например «не работал с EKS в production», и создавать впечатление соответствия требованию. Метка заменена на нейтральное «По резюме» с иконкой документа. Состояние «Уточнить» сохранено. Изменение применяется и к отдельной таблице, и к отчёту.

## Границы проверки

Это проверка локального продукта и состава для первой публикации исходников. На момент этого прогона рабочий каталог ещё не имел собственной истории Git и настроенного remote; история уже существующего репозитория GitHub не проверялась, push в рамках прогона не выполнялся. При публикации нужно использовать Git с текущим `.gitignore`, а не выгружать всю рабочую папку архивом.

Мобильные сценарии проверены эмуляцией Chromium; физические телефоны, Safari, Firefox, Linux/macOS и нагрузочный многопользовательский режим не проверялись. У приложения нет авторизации; публичное размещение API требует отдельной подготовки. OCR и восстановление незавершённых заданий загрузки после перезапуска не реализованы.

Конечный набор успешных ответов не гарантирует качество на любом резюме. Для демонстрации и решений по кандидатам нужна проверка выводов по источникам.

Шесть новых платных вызовов оценены по токенам в `$0.00493`; накопленная оценка всех проверок — `$0.23376`. Консервативное резервирование по журналу — `$4.44` при общем лимите `$5`. Это расчёт тестового журнала, не выписка биллинга OpenAI; встроенного денежного лимита в основном приложении нет.
